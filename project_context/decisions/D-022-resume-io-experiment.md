# D-022 — EX-017 재실험 및 발생 오류 중심 패치

- Status: Accepted
- 날짜: 2026-09-08
- 근거: 사용자가 전달한 「EX-017 재실험과 발생 오류 중심 패치」 구현 지시.

EX-020에서 기존15장면 구조·의미 및 사후3건 → fake 병렬12판 → Cloud 행동180호출과
별도 요약 gate → Cloud 병렬12판 → 비교48판을 순서대로 재개한다. D-019 조건·개발 팀·
대응 일정·seed와10/10/10, retry_transient=0을 유지한다. 최적 행동 일치는 통과 기준이 아니다.
Cloud 행동은15×B/C×요청동시성1/10×3이다. C 입력 요약 생성은 별도 분모다.
EX-016의30행동 이상 원자료4개에서 요약3회·통합1회를3반복해48호출을 검증한다.
출력/호출 실패0, 사실·시점·identity 통과, 실제 HTTP 겹침10 및 p95비율≤2를 요구한다.

현재0.11.0+ruination-v1에서 출발한다. 재실행에서 실제 발견된 계산·입력 오류만 해당
판단·기술·원응답·source와 연결해 보존하고 신규 작업을 멈추며 진행 중 작업을 정리한다.
Pinned Showdown 독립 최소 fixture로 재현 후 필요한 입력 전달과 프로젝트 소유 패치를
수정할 수 있다. 패키지 버전은 유지하고 engine_patch 구조에 새 ID/해시를 부여한다.
양성·음성 및 전체 integration 회귀 후 새 source로 오프라인부터 도달 단계까지 재검증한다.
비공개 상대 정답은 행동 입력에 금지하며 미상 행동은 조건부/미상으로 표현한다.
EX-019 문제 전체 수정·진단 확대, 프롬프트/전략 변경·재질문은 제외한다.
모델 출력·요약 및 provider·환경·무결성 오류에는 기존 중단 규칙을 유지한다.

EX-017/018/019 및 실패 receipt는 보존한다. EX-020 단계·패치 전후 cohort는 합치지 않는다.
48판 도중 패치하면 기존 집단은 중단 자료이며 새 source에서48판 전체를 다시 시작한다.
최초 Cloud 호출부터4시간,3시간45분에 신규 작업/요청 중지·취소하며 패치/재검증도 포함한다.
재시작으로 시계를 초기화하지 않는다. 비교는 smoke 기반 추정×1.5가 남은 예산에 들어갈 때만
시작한다. 기술명→상황→수정→재검증→현재 단계 순으로 보고하고 조건별 예정·시도·완료·
실패·미실행, 대응 누락·승패·역할별 호출/token/시간을 기록한다. Gate/예산 중단 시 EP-011은
완료 처리하지 않는다.
