# D-028 — 요약 thinking low/max 독립 진단

- Status: Accepted
- 날짜: 2026-09-08
- 승인 근거: 현재 사용자가 제공한 「요약 오류의 thinking 영향 진단: low 대 max」 계획의 구현·검증·132호출·검토·보고 지시.

동일 glm-5.3-flash·v1.1.2·입력에서 summary/summary_rollup의 thinking만 low/max로 비교한다.
[공식 모델 설명](https://ollama.com/library/glm-5.3-flash)의 low/high/max 지원을 2026-09-08 확인했다.
SDK는 수정하지 않고 진단 전용 호환 어댑터로 검증된 think를 직렬화한다. 두 조건은 같은 전송 경로다.

EX-024 고유 경계의 첫 요약8·후속10·통합4, 각 조건3반복으로132호출(각66)이다.
이전 요약과 통합용3요약은 해당 경계 이전 원문에서 작성·검토·고정한다. 생성 응답 재사용은 없다.
기존125필수 사실을 원문 재대조하고 입력별 기준·고정 메모리 근거를 최초 Cloud 전에 봉인한다.
평가 기준·미래·상대 비공개 정보는 모델 입력에 넣지 않는다.

모델/프롬프트 외 고정값은 temperature0, seed100, 출력131072, provider 기본 context,
timeout300초, 계정/모델10/10, 재시도0이다. 순서 seed20260908, 반복별 선행 조건 균형 교대다.
독립 backend/context를 사용하고 실제 직렬화 think·trace와 반환 model/usage/종료 사유를 보존한다.
이는 서버 내부 추론량의 직접 확인이 아니다. 기본값과 행동 역할은 low를 유지한다.

조건/thinking/token/지연을 가린 응답에 필수 사실 retained/incorrect/omitted와
오류 문장·원문 행·설명을 기록한다. 주지표는 사실·진영·시점·identity·형식 오류 또는
필수 누락이 하나 이상인 응답 비율이다. 보존율·개별 오류/누락·단정/모순·재발·token·HTTP
p50/p95·실제 배치 시간도 보고한다. 입력별3반복을 먼저 집계하여 max−low를 산출하고
첫/후속/통합을 구분한다. 전체는 원배틀별 평균에 동일 가중치를 주며 경계·진영·반복을
독립 표본으로 세지 않는다. Kyurem 과거 Choice lock, Spikes 진영, 실제 발생 턴,
소모·종료 상태 복원을 사전 지정 재발 항목으로 보고한다.

사전311회귀 범위·추가 직렬화/역할/해시/상태 검사, 오프라인15장면·사후3건,
22입력/고정 메모리 원문 대조, fake132 집계/중단/선봉인/중복거부 후 Cloud에 진입한다.
사전 입력 오류는 독립 재현·수정·재검증한다. 최초 Cloud부터4시간,3시간45분 신규제출 중지다.
유료 상한132, probe/재질문/실패보충/Cloud채점/실행 중 수정은 금지한다.
모델 오류는 측정하고 수집 계속, provider/환경/입력/평가/무결성 오류는 전체 중단한다.

132응답 근거 검토·대응집계·자원정리·상태 갱신까지 완료해야 진단 완료다.
시간초과/검증실패에는 예정/제출/응답/검토/실패/미실행/미확정/누락대응을 명시하고 미완료다.
오류 감소는 이 개발자료에서의 탐색적 근거이며, 지속/무차이는 max로 해결되지 않았음을 뜻한다.
모델이 유일 원인이라는 결론, 실제 연쇄 누적·운영 적용·행동/실배틀/48판·IO 재개는 범위 밖이다.
EX-020~024 원자료·무효·halt·clock 및 EP-011/012/013 Blocked는 보존한다.
