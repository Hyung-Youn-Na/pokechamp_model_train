# D-127 — Qwen3.5-0.8B 행렬 탐색 고정 대진 자기대국 학습

- 상태: Accepted
- 날짜: 2026-10-07
- 근거: 사용자 요청 "qwen 4B는 매우 무거우니 Qwen/Qwen3.5-0.8B-Base 로 MCTS로 학습을 설계해보고 싶습니다.
  시간 제한 없이 성능 개선이 어느정도 둔화 될떄까지 학습 계획을 세워주세요. GPU는 2,3번 GPU를 사용해주세요."
  계획 단계의 사용자 선택은 행렬 탐색, 직전 대비 둔화+100라운드 상한, 등록을 미루고 먼저 시작이며, 계획을 승인했다.

## 결정

[EX-080](../experiments/EX-080-qwen-matrix-selfplay.md)을 EX-079와 독립된 새 고정 대진 실험으로 등록하고 실행한다.

- **모델:** Qwen3.5-0.8B-Base LoRA. 학습 데이터는 자기대국뿐이며 과거 자료·가중치는 쓰지 않는다.
- **탐색:** 루트 전폭 행렬 탐색(동시행동, 사전 정책 magnet MMD 정규화 균형)을 쓴다. 탐색 잡음 없는 정책 타깃을 쓴다.
- **종료:** 4라운드마다 직전 평가 모델과 비교한다. 둔화하면(3회 연속 0.55 미만, 최소 12라운드) 종료하고, 상한은 100라운드다. 시간 상한은 없다.
- **최종 시험:** 잠긴 test640을 1회 수행한다. GPU는 물리 2·3번만 쓴다.

조건 원문은 EX-080, 실행 진행은 [EP-132](../exec-plans/completed/EP-132-qwen-matrix-selfplay.md)가 소유한다.

## 등록 유예 예외

실행 중인 EX-079는 재개·최종화 때 `RESEARCH_DESIGN.md`·`CONTRACTS.md`·`CHARTER.md`,
`integration/pokechamp/**`, venv 패키지 목록 등을 다시 해시한다(`fixed_matchup/prepare.py:16-65`).
사용자는 EX-079 종료를 기다리지 않고 먼저 시작하기로 선택했다. 그래서 다음 순서를 따른다.

- EX-079 종료 전에는 이 결정과 EX-080이 조건·실행 경계의 원문이다.
- EX-079 종료 receipt와, 같은 범위를 해시하는 다른 실행이 없음을 확인한 뒤 다음을 한다.
  - RD 고정 대진 목표 절에 EX-080을 편입한다.
  - CONTRACTS에 C-061(Qwen 고정 대진 행렬 탐색 경계)을 등록한다.
  - 이 사후 편입은 실행 중인 EX-080의 조건을 바꾸지 않는다.
- 코드는 EX-079 해시 범위 밖의 `integration/qwen_mcts/`에 둔다.
  - 필요한 기존 코드는 복사하고 원본 해시를 기록한다.
  - 공유 venv에는 아무것도 설치하지 않는다. GPU0·1은 쓰지 않는다.
- EX-080의 live 재검증 범위는 코드·의존성·모델·팀이다. 수일 실행이 다른 작업의 문서 편집 때문에 막히지 않도록,
  RD·CONTRACTS·CHARTER·EX/D 문서는 준비 시점 사본만 보존한다.

## 대안과 이유

- **Exp3 MCTS에 최소 교정만 하는 안:** EX-079와 비교하기는 쉽다. 하지만 현 탐색은 사실상 1-ply이고 γ 균등 성분이 들어가며,
  EX-079 round1~4의 탐색 없는 정책 점수가 0.469로 변하지 않았다. 사용자 선택에 따라 행렬 탐색을 채택한다.
- **P0 대비 앵커로 종료하는 안:** P0 대비 점수가 포화되면 실제로는 개선 중이어도 일찍 끝날 수 있다. 그래서 직전 평가 대비를 채택한다.
- **Qwen3.5-4B:** 현재 탐색 호출 수 기준으로 라운드당 30~46 GPU·시간이 든다고 추정되어 채택하지 않는다.
- **EX-079 종료 후 시작하는 안:** 사용자가 먼저 시작하는 쪽을 선택했다.
