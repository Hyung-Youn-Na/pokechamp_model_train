# D-197 — laya v2+테라(EX-124) fix 입력에서 테라 합산 결정과 테라 방어 문구 배틀(재학습 없음, GPU1)

- 상태: Accepted
- 날짜: 2026-10-27

## 맥락

- 사용자 질문(2026-10-27): 모델이 테라를 거의 쓰지 않는 이유는 무엇인가? 분석은 EX-125 v2t 128경기 로그와 v2-all 학습 행으로 했다(읽기 전용).
  - 모델의 결정당 테라 확률 합 평균은 3.40%로 사람의 선택률 3.41%와 같다. 턴에 따라 늘어나는 모양도 사람과 같다.
  - 하지만 테라를 쓴 경기는 17%(22/128)로 사람 78.8%의 약 1/4이다. 확률이 여러 결정에 나뉘어 있어서 1순위만 고르는 서빙에서는 테라가 거의 뽑히지 않는다.
    - 결정당 테라 확률 합 중앙값은 0.009이고, 0.5 이상인 결정은 0.19%다.
    - 테라 확률 합이 0.3 이상인데 테라가 아닌 행동을 고른 38결정 중 27결정은 같은 기술의 일반 선택지가 1순위였다.
  - 테라 선택지 문구는 공격 쪽(자속·피해)만 바뀐다. 테라/일반 쌍의 90.2%는 태그 외 문구가 같고, 사람이 테라를 쓴 행의 46.4%도 문구 차이가 없다. 방어 상성은 입력에 없다.
  - EX-124는 방어 상성 지식(A2 테라 후 방어 타입, A3 테라 후 상대 기술 배율, B1 테라 후 가장 아픈 공개 기술)을 held-out 91~100%로 배웠지만, 사람 테라 행의 테라 확률은 바뀌지 않았다.
- 사용자 결정: (1) 결정 규칙만 바꾸는 실험, (2) 입력에 테라 후 방어 상성을 넣는 재학습 없는 간이 시험을 같은 실행에 둔다. 입력은 EX-139의 fix(v2 형식, 아이템 상태로 보정한 값)로 한다.

## 결정

1. **재학습은 없다.** EX-124 selected(`12519d98…`)를 `v2fix` 입력으로 세 가지 서빙한다.
   - `laya-v2t-fix-tp1`, `laya-v2t-fix-tp3` — **테라 합산 결정**(k=1, 3).
     - 테라 선택지 확률을 모두 합쳐 k배 한 값을 가장 높은 테라 선택지 하나에 두고, 다른 테라 선택지는 0으로 둔 뒤 정규화한다. 이 결정 분포의 1순위를 고른다.
     - 결국 "k × 테라 확률 합 > 테라가 아닌 행동 중 최고 확률"일 때 테라를 쓴다. 테라 선택지가 없거나 규칙이 작동하지 않는 결정은 기존 1순위와 같다.
     - EX-071 플레이어의 1순위 검사(`player.py`, 수정 금지)를 그대로 통과하도록 응답 `probabilities`에는 결정 분포를 넣는다. 모델의 원래 분포는 `model_probabilities`로 따로 기록한다.
     - k=3은 EX-125·EX-139 fix 로그에서 계산한 테라 사용 경기(77%, 74%)가 사람 78.8%에 가깝도록 정했다. 승패는 보지 않았다. 같은 일정에서 고른 값이라는 점은 한계로 둔다.
   - `laya-v2t-fix-tdef` (`--render v2fixtd`) — **테라 방어 문구**, 1순위 선택.
     - `move:*:tera` 선택지 문구의 `; terastallize <타입>` 바로 뒤에 테라 후 방어 상성을 교체 후보와 같은 문구로 붙인다: `; takes <상대 타입> xN …; worst xN`.
     - `takes`는 상대 포켓몬 타입이 테라 타입에 들어가는 배율, `worst`는 상대가 공개한 공격 중 테라 후 가장 아픈 배율이다. Stellar는 타입이 바뀌지 않으므로 붙이지 않는다.
     - 학습 때 테라 선택지에 없던 문구이므로 분포 이동이 있다. 간이 시험이다.
2. **비교 기준**은 EX-139 `laya-v2t-fix`(같은 체크포인트, 같은 입력, 1순위)의 같은 EX-120 슬롯이다.
   - tp 조건은 규칙이 처음 1순위를 바꾸기 전까지 EX-139 fix와 같은 경기여야 한다. 규칙이 한 번도 작동하지 않은 슬롯은 결과·턴 수가 같아야 한다(재현 검사).
   - EX-139 봉인과 `result.json` 해시를 prepare 시점에 동결한다. EX-125 v2t는 참고 행이다.
3. **판정**(실행 전 동결): 조건별 같은 슬롯 점수 차이(조건 − EX-139 fix), 조합 32 클러스터 bootstrap 95%(10,000회, 시드 20261040). 하한 > 0 개선, 상한 < 0 악화, 그 외 구별되지 않음. 정상 종료 120/128 미만은 보류. tp3 − tp1과 EX-125 대비는 보고 전용이다.
4. **자원**: GPU1(`gpu1.lock`)과 포트 8109(`port8109.lock`)만 쓴다. EP-218(GPU0·GPU2, 8107·8108)과 외부 프로세스(GPU3)는 건드리지 않는다. 코드는 새 파일과 최소 덧붙이기로만 바꾸고, EX-136이 `training`인 동안에 끝낸다.
5. 오프라인 결과로 배틀을 거르지 않는다([D-191](D-191-no-offline-battle-gate.md)).

## 대안

- **샘플링 서빙**: 테라 외 결정까지 무작위가 되어 EX-139와 같은 슬롯 비교와 재현 검사가 깨진다.
- **기술 단위로 합친 뒤 테라 여부 판단**: 일반 기술 선택도 바뀌어 결정 규칙의 효과를 테라로만 분리할 수 없다.
- **방어 상성을 넣은 렌더러로 재학습**: 근본 대응이지만 자료 생성과 약 10시간의 GPU가 필요하다. 이번 간이 시험 결과를 보고 따로 등록한다.
