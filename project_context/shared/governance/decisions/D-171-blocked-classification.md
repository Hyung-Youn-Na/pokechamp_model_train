# D-171 — Blocked 계획의 별도 관리 분류

- 상태: Accepted
- 날짜: 2026-10-20
- 승인: 사용자가 제안된 네 분류에 동의하고 “별도 분류해줘”라고 지시함

## 결정

당시 실행의 Blocked 판정과 현재 처리 필요 여부를 분리한다.
기존 EP·EX의 상태·결과·조건·봉인은 수정하지 않으며 원문을 이동하지 않는다.
`catalog/blocked.json`에서 관리 분류·이유·근거 ID·후속 ID를 관리하고
`catalog/blocked.md`를 생성한다. 분류는 다음 네 가지다.

- 해결 대기(awaiting): 남은 장애와 현재 이어갈 필요가 모두 근거로 확인됨.
- 후속 해결·종결(resolved): 명시된 후속 교정·재실험·계승이 처리 범위를 충족함.
  조건 변경을 동반한 대체도 명시하며, 원인 영구 해소나 원실험 성공을 뜻하지 않는다.
- 진행 종료(ended): 해당 실행/작업을 더 진행하지 않는다는 명시적 종료 근거가 있음.
  연구 주제 전체의 폐기를 뜻하지 않는다.
- 확인 필요(review): 후속 처리 범위·잔여 작업·현재 진행 필요가 불명확함.
  분류가 없는 새 Blocked도 이 항목에 표시하여 누락하지 않는다.

후속이 존재하거나 Completed라는 사실만으로 원계획을 자동 종결하지 않는다.
부분 교정, 다른 평가 과제의 완료, 정책 기준 변경과 원래 기준 충족을 구분한다.
네 분류 모두 현재 실행 승인이 아니며 scope가 겹치는 중단 원문 확인 의무를 유지한다.
Paused는 별도 일시 중지 상태로 유지하고 Blocked 분류에 혼합하지 않는다.

## 적용

분류 단위는 Blocked EP이며 관련 EX를 함께 연결한다. 원문 상태는 계속 개별 EP/EX가 소유한다.
전체 계획 색인에는 Blocked 세부 목록 대신 네 분류별 집계·연결을 제공한다.
근거와 분류가 바뀌면 sidecar를 갱신하고 catalog build/check를 수행한다.
작업·검증은 [EP-186](../plans/EP-186-blocked-classification.md)을 따른다.
