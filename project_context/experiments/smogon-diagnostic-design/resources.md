## 64경기 기본 추정과 장기전 감도

기본안은 A16 실측을4배한다. 장기전2배/4배는 모든64경기의 요청 수가 각각2배/4배가 되고,
요청당 입력이 추가로1.5배/2배 커지는 **가정**이다. 요청당 출력과 HTTP 지연은 일단 같다고 둔다.
따라서 입력은 기본 대비3배/8배이며, 실제 latency가 길어진 입력에 따라 증가하면 시간은 더 늘 수 있다.
새 팀의 실측이나 신뢰구간·최악 상한은 아니다.

## watchdog과 해석

EX-033의 요청 timeout300초·경기 watchdog1200초를 유지한다. 평균 actor 시간을2배하면
약859초,4배하면 약1,718초여서 뒤 가정은 평균만으로도 watchdog을 넘는다.
기존 최장1,017.64초 경기도 여유가 적다. 위 장기전 표는 **중단으로 잘리기 전 필요한 자원**을
보는 민감도이며, 현 watchdog에서 그만큼 기다려64경기를 자연 종료시킬 수 있다는 예측이 아니다.
Watchdog 경기에는 패배를 배정하지 않고 실패로 분리한다. 이로 인해 남은 유효경기 승률이
짧은 경기 위주로 치우칠 수 있어 길이·실패·미실행 분모를 함께 보고한다.
이번 설계를 완성하려고 timeout을 늘리거나 무효 경기 보충을 추가하지 않는다.

기본 예상 검토량은 `476×4=1,904`결정이며 장기전에서는 늘어난다. 자료 정리·사람의 전수 검토·
도구 구현 시간은 배틀 벽시계 추정에 포함하지 않는다. 추가 모델 심사 호출은 계획하지 않는다.
Token은 provider 응답 계측값이지 청구 금액이 아니다. 금액 자료가 없어 USD/KRW를 임의 산정하지 않았다.

후속 실행 시 request/token/경과시간은 최초 Cloud 시각부터 누적하고 실패·미확정·원본 IO
추가 호출을 차감하지 않는다. 금액·시간·요청 상한과 정리 여유는 실행 승인에 명시할 별도 값이다.
EX-033의 무상한 정책을64경기로 확대하지 않는다. 새 budget/clock을 이번 준비에서 만들지 않았다.
