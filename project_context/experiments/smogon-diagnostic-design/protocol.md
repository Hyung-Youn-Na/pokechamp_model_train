# EX-034 — 대진·행동 검토·해석 protocol v1

사전 설계일은 2026-09-11이며 대전 결과를 보지 않고 고정했다. 이 문서는 연구 명세이며
실행기 API 또는 실행 승인이 아니다. [EX-034](../EX-034-smogon-diagnostic-design.md)의 범위를 따른다.

## 대진과 무작위성

`schedule.json`을 행별 대진의 원본으로 사용하고 `schedule.csv`는 같은 내용을 표시한다.

| 축 | 값 | 예정 경기 |
|---|---|---:|
| 운용 과제/탐색팀 | setup/S1, hazards/H1, preservation/R1, limited_turns/W1 | 각16 |
| 기존 anchor | legacy-2, legacy-6 | 각32 |
| 상대 정책 | abyssal, one_step | 각32 |
| 팀 배정 | A_new: A가 탐색팀 / A_anchor: 상대가 탐색팀 | 각32 |
| 반복 | 1, 2 | 각32 |
| A 진영 | p1, p2 | 각32 |

총4×2×2×2×2=64이며 **팀 배정과 p1/p2는 별도 축**이다. 각각의
과제×anchor×정책×배정 셀32개에는 반복2개와 양 진영이 있다. 모든 게임 seed는64개 서로 다르다.
`A_new`는 해당 팀의 운용, `A_anchor`는 그 팀에 대한 대응을 관찰한다. 두 배정의 승률을
합쳐 A가 탐색팀을 직접 운용할 때의 실력으로 표시하지 않는다.

생성 master seed는 `20260911`이다. ASCII 문자열 `EX034|20260911|<label>`의 SHA-256에서
게임 seed는 앞8바이트를 big-endian uint16 네 개로, actor seed는 앞4바이트를
big-endian 정수로 읽어 `2**31` 나머지로 만든다. label은 생성 도구에 명시된
`battle|slot_id`, `actor-A|slot_id`, `actor-opponent|slot_id`다.
각 셀의 `seat|cell_id` 첫 바이트 짝홀로 반복1 진영을 정하고 반복2는 반대로 한다.
`order|slot_id` 전체 digest 오름차순이 제출 순서다. RNG 라이브러리 버전에 의존하지 않는다.
[생성 도구](../../exec-plans/evidence/ep028/build_schedule.py)는 대전을 실행하지 않는다.

모델 seed100은 모든 요청에 고정한다. Python random·NumPy·PYTHONHASHSEED는 각 actor seed를
사용하고 Showdown 경기 seed는 해당 행의 네 정수다. Worker root seed는 EX-033과 같은
`100,100,100,100`이다. 기존 서버의 경기별 seed 전달·실제 사용
대조 방식을 유지한다. 팀 선택 RNG는 없으며 팀 원본 순서도 보존한다. Team preview 선봉 결정은
원본 A/상대 정책에 맡긴다. 초기 p1/p2 팀·계정·seed 기록을 원본 표와 대조한다.

배틀/계정/모델 동시성 상한은10을 기준안으로 한다. 위 순서는 **신규 slot 제출 순서**이며
동시 실행의 완료 순서·HTTP 요청 교차 순서까지 고정했다는 뜻은 아니다.
반복2에서 게임 seed와 진영이 함께 달라지므로 진영 효과의 독립 추정은 할 수 없다.
모델/provider의 비결정성까지 제거했다고 주장하지 않는다. 원본에서 생략된 성별을 Showdown
TeamValidator가 `Math.random()`으로 채우는 별도 경로도 있다. 원본을 임의로 수정하지 않고
실제 검증/전송된 packed team을 후속 실행의 증거로 보존하며, 이 seed 명세를 모든 동작의
bitwise 재현 보장으로 표시하지 않는다. 원본 팀 hash는 이 임의 정규화 전 바이트의 hash다.

## 승패·신뢰성 분모

모든 표에는 `planned, attempted, valid_completed, failed, invalid, not_run`을 함께 싣는다.

| 값 | 정의 |
|---|---|
| planned | 사전 고정 slot 수. 전체64, 결과에 따라 삭제하지 않는다. |
| attempted | slot의 실행 시작을 예약하고 실행 기록을 만든 수. HTTP0인 시작 실패도 포함한다. |
| valid_completed | 자연 종료(승/패/무), 실제 행동·입력·증거·환경이 protocol과 일치하는 경기. |
| failed | 시도했으나 provider/timeout/watchdog/경기별 환경·실행 실패 등으로 유효 자연 종료를 얻지 못한 경기. |
| invalid | 입력·설정·수집·무결성 결함과 의존성으로 분석에서 제외한 시도. 자연 종료했어도 해당된다. |
| not_run | 시도하지 않은 예정 slot. 중단 의존 범위·사유를 함께 남긴다. |

종결 시 `planned=attempted+not_run`, `attempted=valid_completed+failed+invalid`다.
아직 처리 중이면 별도 `pending`을 오른쪽에 더한다. 무효화가 실패와 겹치면 최종 집계는
invalid에만 세고 원래 terminal status/category는 보존한다. 종료 미확인 시도는 결과를 추측하지
않고 `failed: outcome_unconfirmed`로 종결하며 수집 요청의 미확정 여부도 별도 남긴다.

유효경기는 `W+L+D=valid_completed`, 승률은 `W/valid_completed`, draw-adjusted score는
`(W+0.5D)/valid_completed`다. 유효 분모0은 N/A다. 정책×팀 배정×과제별16개 표(각 예정4),
anchor와 반복/진영까지의 원시64행, 정책별/과제별 요약을 제공한다.
정책 동일 가중 평균은 두 정책의 해당 점수가 모두 존재할 때만 보조 지표로 산출한다.
누락이 있으면 관측 경기의 기술통계이며 완전 균형 비교로 부르지 않는다. 유효64/64가
아니면 경기 수집 완료라고 하지 않되 관측된 실패와 모든 전수검토 결과를 보고한다.

과거 EX-033의 A14/16과 새 팀 성적을 독립 동일분포 표본으로 합치거나 승률 차이를
팀 과제의 인과 효과로 해석하지 않는다. 표본은 의도적으로 고른 팀과 두 정책의 개발 대진이다.
64경기·수백 행동이64개 독립적인 전략 검증이라는 가정은 하지 않는다. 작은 셀2회의 승률로
순위·유의성·동등성을 주장하지 않는다. 전체 집계보다 팀/정책/배정별 결과와 증거를 우선한다.

## 모든 A 행동의 증거 연결

승패·출력 정상 여부와 관계없이 A의 `decision_start` 전체를 검토한다. Team preview,
강제교체, 단일 후보의 자동 선택, fallback, 실패 경기의 마지막 미전송 결정도 포함한다.
모델 호출이 없는 행동에는 입력/출력 칸을 `not_called`로 두고 실행 정책 근거를 연결한다.
한 decision에 여러 원본 IO 호출이 있으면 마지막 응답만 남기지 않는다.

검토 행은 최소 다음 필드를 갖는다. 이는 새 공개 API schema가 아닌 분석 기록 양식이다.

| 묶음 | 필수 필드 |
|---|---|
| 식별 | experiment/slot/attempt/actor/decision_seq, showdown_turn, request_id, task, team_assignment |
| 실제 전달 | 원본 bundle와 seal, events.jsonl 및 event_seq, system/user prompt, intent/response 파일과 hash, 각 call_seq |
| 실행 연결 | 원출력, upstream 추출/파싱 판정, 선택 행동, fallback 단계·선택 출처, wire_action의 event_seq/문자열, 서버 수락/거절·다음 공개 로그 |
| 시점 | 판단 직전 공개 prefix의 마지막 event_seq, 현재 자기 상태/합법 행동 근거, 모델에 실제 도달한 사실과 미도달 사실 |
| 검토 | opportunity tag, 아래 판정과 근거, 관측 사실/조건부 추론의 구분, 대안과 필요 가정, 오류의 최초 시점·의존 범위, reviewer/date/rubric version |
| 불확실성 | unknown/미검토 이유, 반대 증거, 검토 후 수정 이력 및 원본 annotation hash |

`decision_start → 해당 llm_call들 → decision_result → wire_action → 공개 protocol`을
join한다. 출력이 합법이라고 실제 전송으로 간주하지 않으며, 전송됐다고 서버 수락으로 간주하지 않는다.
시작·결과·전송 수가 다른 이유도 전수 대사한다. Viewer 링크는 편의 수단이며 hash가 있는
원자료가 근거다. 새 도구가 필요하면 별도 구현 범위에서 다루고 원본을 수정하지 않는다.

첫 전략 검토에서는 승패와 이후 로그를 보지 않고 decision 직전 prefix·실제 모델 입력으로
판정한다. 이후 전개는 별도 영향 분석에 연결한다. 연구자가 가진 상대 전체 paste의 숨겨진
기술·item·EV를 그 시점에 A가 알았던 사실로 사용하지 않는다. 자기 팀 정보도 실제 입력에
있는지 따로 확인한다. 원본에 저장된 완전한 battle_state가 곧 모델 전달 입력은 아니다.

## 판정 종류와 오류 인정 기준

분류는 원인과 현상을 분리하며 중복 tag를 허용한다. 상충하면 미확정으로 남긴다.

| 분류 | 기준과 처리 |
|---|---|
| 판단의 사실/규칙 오류 | 실제 입력에 근거가 있고 pinned 규칙과 명백히 모순된다. 명시된 설명 또는 행동의 필수 전제로 확인한다. 설명 없는 행동에 가상의 믿음을 부여하지 않는다. |
| 전략적 판단 오류 | 시점 정보·합법 대안·필요 조건이 충분하며 주장하는 열위가 숨겨진 상대 set/향후 난수에 의존하지 않는 근거를 제시할 수 있을 때만 확정한다. 단순 팀 해설 불일치는 부족하다. |
| 전략 미확정 | 대안 우위가 특정 읽기, 숨겨진 기술/EV, 명중/급소, 피해 roll, 평가자 취향에 의존하거나 장기 반사실을 검증할 수 없다. 의심 후보와 확인 조건만 남긴다. |
| 원본 입력의 정보 누락/오류 | 자기/공개 prefix 사실과 실제 전달 prompt의 차이를 기록한다. 원본 변환의 의도된 노출 범위인지, 원본 구현의 잘못된 사실인지, 새 수집 이탈인지 구별한다. 입력 유발과 모델 단독 오류를 섞지 않는다. |
| 출력·실행 실패 | parse/후보 매칭/fallback/전송/서버 거절/provider/timeout을 단계별로 기록한다. 합법 전송으로 복구돼도 원출력 오류를 삭제하지 않는다. |
| 오류 근거 없음 / 미검토 | 검토해서 근거가 없는 것과 아직 검토하지 않은 것을 구분한다. 둘을 정상 판단 확증으로 부르지 않는다. |

기계적 사실은 pinned Showdown의 기술·특성·상태 지속 규칙과 공개 로그를 근거로 사용한다.
피해 우위를 주장하려면 실제 시점 입력/알려진 범위와 난수 범위를 명시한다. 커뮤니티의 계산·EV
의도는 외부 운용 설명이며 독립 기계 검증 없이 정답표로 승격하지 않는다.
샘플 팀 해설을 읽은 사람이 선택했을 법한 행동을 A의 의무로 정하지 않는다.

원본 IO가 정보를 본래 생략하거나 틀리게 전달하는 것은 진단 대상 baseline의 한계로 별도
보고한다. 이를 고쳐서 같은 A라고 부르지 않는다. 기술적으로 수집이 원본과 일치한 경기는
그 노출 특성과 fallback을 포함하여 성적에 남긴다. EX-033 기준에서 이탈한 새 입력/처치/수집
결함은 C-018에 따라 영향 경기·의존 결과를 무효화하고 관련 범위를 중지한다.

## 과제별 관측 기회와 검토 질문

| 과제 | 기회 tag와 관측 기준 | 검토할 선택 |
|---|---|---|
| 셋업·공격 순서 | `setup_window`: 합법 셋업 또는 축적 boost가 존재; `breaker_cleaner`: 공개된 방어 포켓몬과 마무리 수단이 관련됨 | 즉시 공격/셋업/교체 순서, 교체로 잃는 boost, Terastallize의 비용. 위험한 셋업이 항상 오류는 아니다. |
| 교체·설치기 누적 | `hazard_cycle`: 설치/제거/차단/Knock Off/피벗 선택과 공개 hazard 상태가 관련됨 | 누적 피해, Boots와 공개 면역, pivot 이후 진입, Court Change/Defog의 양측 효과. hazard 최대중첩을 무조건 목표로 삼지 않는다. |
| 회복·핵심 보존 | `recovery_window`: 회복/Wish/Regenerator 또는 대체 방어수단 부재가 관련됨 | 회복 타이밍, Wish 수신자, 상태/PP 소모, 희생과 보존의 교환. HP가 줄었다는 이유만으로 오류로 세지 않는다. |
| 제한된 턴 | `timed_window`: sun/Trick Room 등 유효 상태 또는 합법 재설정 수단이 존재 | 설정·교체에 드는 턴, 잔여 지속시간의 알려진 범위, 날씨 교체, 종료 후 속도/공격 계획. 공격하지 않은 턴을 자동 낭비로 세지 않는다. |

이 기준은 행동에 여러 tag를 붙일 수 있게 하며, 과제의 **노출 기회 수**를 결과와 함께 보고한다.
각 과제의 검토완료/전체기회, 확정판단오류/검토가능기회, 입력문제, 출력·실행문제, 미확정,
미검토를 분리한다. 분모0은 N/A이며 기회가 없었다면 능력을 시험했다고 주장하지 않는다.
모든 행동 오류율도 별도로 제공하되 장기전의 행동 수가 전체 비율을 지배할 수 있음을 밝힌다.
한 번의 잘못된 상태 기억에서 이어진 여러 턴은 사건 cluster로 함께 묶어, 결정 수와 사건 수를 둘 다 센다.

## 반복 패턴과 보류 팀의 후속 확인

패배는 오류의 필요조건도 충분조건도 아니다. 승리 경기의 실수·패배 경기의 타당한 선택도 포함한다.
동일한 구체적 실패 유형이 **서로 다른 게임 seed의 최소2경기**에서 증거와 함께 관찰될 때
반복 후보로 등록한다. 같은 경기의 연속 턴2개는 해당 기준을 충족하지 않는다.
이 문턱은 후속 가설 정리용이며 한계의 통계적 확증 기준이 아니다.

후속 가설에는 발견 경기/결정, 입력 충분성, 가능한 원인, 반대 사례, 예상되는 관측 기회,
S2/H2/R2/W2 중 대응 팀, 재현/미재현/판정불가 기준을 기록한다. 해석 범위를 넘는 전이는 제한한다.
예를 들어 sun 전용 날씨 규칙 오류를 W2의 Trick Room으로 확인할 수 없다. W2는 제한된 턴의
설정·피벗·공격 순서라는 일반 가설에만 사용한다. 날씨 전용 가설에는 별도 팀 설계가 필요하다.
64경기 이후 rubric·팀·prompt를 조정했다면 그 사실과 버전을 공개하고 탐색 결과와 분리한다.
이번 준비는 후속 대진/예산/실행을 자동 승인하지 않는다.

## 실패·복구·종결

각 slot 최초1회, provider retry0, 보충/재수집0이다. A의 원본 IO 파싱 재질의(기존 최대10)와
fallback은 baseline 동작이며 그대로 계측한다. EX-033 A457요청은 모두 첫 IO 시도였다.
이 값을 provider 오류 재시도나 경기 보충을 허용하는 근거로 사용하지 않는다.

경기별 provider·timeout300초·watchdog1200초·환경 실패는 해당 경기를 종료한다.
출력/설명 오류가 있어도 baseline 경로로 자연 종료하고 증거가 온전하면 유효경기에 포함한다.
합법 후보 부재·공유 입력/설정/수집/격리 무결성 문제·공유 permit 실패는 영향 범위의 신규
제출을 중지한다. 영향 불명확은 잠재 전체 중지다. C-018에 따라 원인·최초오염·의존관계·
수정 전후 버전·독립 검증·별도 평가를 기록한다. 재수집0이므로 결함을 고친 뒤 같은 slot을
다시 실행하지 않는다. 평가 구현만 잘못되고 응답이 온전하면 같은 사전 기준으로 모든 영향
자료를 재평가한다. rubric 교정은 별도 사후 수정 분석이며 기존 판정을 덮어쓰지 않는다.

실행 승인 시 최초 Cloud 시각, 누적 요청/확정 token/실패/미확정, 예산·시간·요청 상한과
정리 여유를 명시한다. 현재 유료 시계는 시작하지 않았으며 EX-033의 무상한 승인을 상속하지 않는다.
중단 시 미실행 사유, 수집분 전수 검토, 원자료 봉인, 소유 프로세스/permit 정리까지 보고한다.
